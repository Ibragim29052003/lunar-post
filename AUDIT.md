# Аудит игры Лунная почта

Все обязательные требования задания реализованы. В проверенных игровых сценариях блокирующих дефектов не осталось. Аудит включал чтение исходного DOCX, анализ кода и конфигов, автоматические тесты, визуальную проверку в браузере и проверку готовой сборки.

Дата проверки — 28 октября 2026 года. Проверенная среда команд — Node.js 26.12.1. Исходный бойлерплейт из папки `intern` сохранён отдельно; решение использует его стек React, TypeScript и Webpack.

## Дополнительные возможности

- Два режима с разным темпом и отдельными рекордами.
- Десять уровней сложности, серии и бонусы.
- Web Audio со стартовой мелодией, звуками доставки, промаха, бонуса и проигрыша.
- Пауза по кнопке и клавиатуре, при потере фокуса, уходе со вкладки и открытии инструкции.
- Сохранение рекордов и звука, синхронизация рекордов между вкладками.
- Нативная модальная инструкция, доступные названия элементов и `prefers-reduced-motion`.
- Запуск приложенной production-сборки без установки npm-зависимостей через `npm run preview`.

## Исправления по результатам аудита

1. **Корпус выходил за высоту окна ноутбука.** Размер теперь зависит от высоты окна; старт и продолжение переводят страницу к прибору. Добавлены компактные раскладки для маленького телефона и альбомного режима.
2. **LESS преждевременно вычислял `min()` с единицами высоты окна.** CSS-выражение сохранено для вычисления браузером. Исправление проверено измерениями, а не только чтением исходного LESS.
3. **Результат на маленьком телефоне обрезался справа.** Внутреннее поле расширялось из-за сочетания `aspect-ratio` и минимальной высоты. Его ширина теперь явно ограничена шириной LCD.
4. **Мышь меняла положение корзины при отпускании кнопки.** Все основные указатели обрабатываются на `pointerdown`. Поздний совместимый `click` не повторяет старое действие. Клавиатура и вспомогательная активация кнопок работают через `click` с нулевым `detail`.
5. **Графика зависела от фиксированных пяти шагов.** Отображение и следы сегментов теперь используют число позиций из конфига. Проверены 3, 5, 7 и 9 позиций.
6. **Подписи могли расходиться с игровым балансом.** Число жизней, очки, серии, подсказки и прямые клавиши связаны с конфигом. Минимальный промежуток между прибытиями также вынесен в конфиг.
7. **Меньший рекорд из другой вкладки мог перезаписать больший.** При сохранении рекорды объединяются через максимум, изменения другой вкладки обновляют интерфейс.
8. **Отказ `localStorage` был незаметен пользователю.** Игра продолжает работать и сообщает, что сохранение доступно только до закрытия текущей страницы.
9. **Первая мелодия могла пропадать при асинхронном разрешении Web Audio.** Звук дожидается запуска контекста. Mute сразу заглушает запланированные ноты; закрытие контекста отменяет отложенное воспроизведение.
10. **При новом рекорде экран результата скрывал количество доставок.** Теперь рекорд, число доставок и лучшая серия показаны одновременно. Равный прежнему результат не считается новым рекордом.
11. **Некоторые ARIA-подписи стояли на неподходящих элементах.** Рекорд и итоговый счёт переведены на семантический `output`. Пять состояний проходят axe-core.
12. **Часть мелких подписей имела низкий контраст.** Вторичный текст затемнён, цвет активных элементов скорректирован, прозрачность подсказки клавиатуры уменьшена. Основная пара цветов LCD имеет расчётный контраст около 6,66:1. Вместо повторного резкого мигания при промахе используется один мягкий импульс; настройка уменьшения движения по-прежнему учитывается.
13. **Маленькие сервисные кнопки были неудобны для касания.** Звук и пауза имеют размер 44 × 44 px; игровые кнопки — от 48 px в альбомном режиме и от 50 px в проверенной портретной раскладке.
14. **При частых правках хеш имени development-бандла менялся.** Имя dev-ассета теперь стабильное; хеширование сохранено для production.
15. **ESLint 8 был устаревшим.** Выполнен переход на поддерживаемый ESLint 10, актуальные TypeScript/Hooks-плагины и Prettier 3 без обхода peerDependencies. Структурная доступность проверяется axe-core в отрисованных состояниях интерфейса.
16. **LCD перерисовывался на каждом шаге симуляции.** Сцена сравнивает видимые позиции посылок, счётчики мемоизированы. Отдельная CSS-карта исходников больше не дублируется в production-JS. Основной бандл уменьшен примерно с 213 до 190 KiB, несмотря на добавленные исправления и счётчики.
17. **Для просмотра архива требовалась установка всех пакетов.** Добавлен статический preview-сервер на стандартных модулях Node.js. Он раздаёт только `dist/`, проверяет реальные пути файлов, возвращает корректные MIME-типы и не принимает лишние HTTP-методы.

## Production и упаковка

Готовая сборка проверена через локальный HTTP-сервер. HTML, JS и favicon возвращают 200, HEAD возвращает заголовки без тела, неизвестный файл — 404, недопустимый метод — 405, неверно закодированный URL — 400. Попытка чтения `package.json` через выход из `dist/` блокируется ответом 403. В ответах есть `X-Content-Type-Options: nosniff`.

В архиве предусмотрены исходники, lock-файл, готовая сборка, инструкция, этот отчёт и скриншоты. `node_modules`, `.git`, временные файлы и материалы исходного задания в архив не включаются. После упаковки выполняются проверка целостности ZIP, распаковка и сравнение файлов с проектом.

## Границы проверки

- Браузерный прогон выполнен во встроенном браузере приложения. Отдельные Chrome, Firefox и физические телефоны в этой среде недоступны; тест размеров окна не заменяет испытание на реальном устройстве.
- Touch/pen проверены автоматическими DOM-событиями. Физический сенсор и вывод звука на конкретные динамики не проверялись.
- axe-core выполняется в jsdom без измерения цветового контраста. Контраст базовых цветов рассчитан отдельно, раскладка проверена визуально. Это не утверждение о полной сертификации WCAG.
- Команды фактически проверены на Node.js 26.12.1. Поддержка веток Node.js 22.15+ и 24 указана по совместимым требованиям зависимостей, отдельные прогоны на этих ветках не выполнялись.
- Рекорды хранятся локально для текущего origin браузера; при смене устройства, адреса или порта они не переносятся. Для этой локальной аркады сервер аккаунтов и глобальная таблица лидеров заданием не требуются.
- Результаты других участников недоступны, поэтому место в конкурсе не оценивается.
